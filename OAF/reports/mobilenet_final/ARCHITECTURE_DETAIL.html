1Input & preprocessing

The model only ever sees a fixed 1×3×224×224 float tensor. Turning an arbitrary uploaded X-ray into that tensor is done with NumPy and OpenCV only — no PyTorch — so the same code runs on a Raspberry Pi:

  1. Read & grayscale. Any format → single-channel 8-bit. Colour inputs are converted by luminance; 16-bit films are min–max normalised to 0–255.
  2. Letterbox to a square. The image is padded (never stretched) with black to the larger side, so aspect ratio — and therefore joint-space geometry — is preserved.
  3. Resize to 224×224. INTER_AREA when shrinking, INTER_LINEAR when enlarging.
  4. Scale to [0,1] by dividing by 255.
  5. Replicate to 3 channels. The grayscale plane is copied three times. The backbone was pretrained on 3-channel ImageNet; the image is never colourised.
  6. ImageNet normalisation. (x − mean) / std per channel with mean = (0.485, 0.456, 0.406), std = (0.229, 0.224, 0.225).

At inference no augmentation is applied. During training only, a clinically constrained set was used — small rotation / translation / scale / shear, horizontal flip (the KL grade is side-agnostic), mild brightness & contrast, light noise — with vertical flip, large rotation, elastic warp and random erasing disabled because they corrupt the joint-space and osteophyte cues.

2The MobileNetV2 backbone

MobileNetV2 is a stack of 17 “inverted residual” bottleneck blocks organised into 7 groups, preceded by one ordinary convolution (the stem) and followed by a 1×1 “head” convolution that widens to 1280 channels. It has 2.23 M parameters — roughly 1/60th of VGG16 — because almost every 3×3 convolution is depthwise (one filter per channel) rather than dense.

2.1  The stem

Conv2d(3→32, kernel 3×3, stride 2, pad 1) → BatchNorm → ReLU6. It halves the resolution to 112×112 and lifts the 3 input channels to 32 feature channels. This is the only “full” (non-separable) spatial convolution in the network.

2.2  The inverted-residual block — the repeated unit

Every one of the 17 blocks has the same three-step shape: expand → filter → project, with a skip connection when the shape is unchanged.

  • Expand — a 1×1 convolution multiplies channels by t (t = 1 in the first block, t = 6 everywhere after). BatchNorm + ReLU6.
  • Filter — a 3×3 depthwise convolution: each of the C·t channels gets its own single 3×3 filter, with no mixing between channels. This is where nearly all the parameter and compute saving comes from. Stride s is 2 in the first block of a downsampling group, 1 otherwise. BatchNorm + ReLU6.
  • Project — a 1×1 convolution brings channels back down to the block’s output width C′. BatchNorm, no activation.
  • Residual — if the block did not change shape (s = 1 and C = C′), the input is added to the output.

This build (mobilenetv2_100) has no squeeze-and-excite and no attention inside the blocks — those slots are Identity.

Resolution drops in five steps (224 → 112 → 56 → 28 → 14 → 7) while the channel count climbs (3 → 32 → … → 320). The final conv_head is a 1×1 convolution that widens 320 → 1280, followed by BatchNorm and ReLU6.

2.4  The feature map F

The output of conv_head is F, shape 1×1280×7×7 — a 7×7 spatial grid with 1280 channels, each cell covering roughly a 32×32-pixel patch of the input. This one tensor is read by both heads: the classifier pools it to a vector, and the Grad-CAM branch keeps its spatial layout to build the heatmap. Exporting it as a second ONNX output is what makes grad-free explainability possible.

3The classification head

Two operations, nothing else between them — this is the fact the whole explainability design rests on.

3.1  Global average pooling

Each of the 1280 channels of F is collapsed to a single number by averaging its 49 spatial cells:

ak = (1 / 49) · Σx,y Fk(x, y)     →     a ∈ ℝ1280

No parameters. It makes the network size-agnostic and, crucially, keeps the map linear from F to the logits.

3.2  The linear classifier

A single fully-connected layer with a 5×1280 weight matrix W and a 5-vector bias b (6,405 parameters — the entire task-specific head):

zc = Σk W[c, k] · ak + bc     c = 0 … 4     (raw logits)

There is no dropout, no extra dense layer, no non-linearity here at inference. The 5 outputs correspond to KL0…KL4.

4Calibration — temperature scaling

Raw softmax(z) from a modern CNN is over-confident: it says 95% when it is right 80% of the time. A single scalar T fixes most of this without touching accuracy:

pc = softmax(z / T)c = exp(zc / T) / Σj exp(zj / T)
  • T > 1 softens the distribution (less peaky); T < 1 sharpens it.
  • T = 1.39 here, found by minimising negative log-likelihood on the validation set only — the test set is never used for this.
  • Effect: expected calibration error drops from ≈ 0.10 to ≈ 0.057. Rankings and argmax are unchanged, so accuracy and QWK are identical; only the confidence numbers move.

All probabilities the system reports — the bars, the OA screen, the abstention check — are the calibrated p, not the raw softmax.

Every downstream answer is a deterministic function of the same 5-vector p — one model, several views. Nothing below has its own trained parameters.

6The explainability branch — grad-free Grad-CAM

Why Grad-CAM here needs no gradients

Grad-CAM weights each feature-map channel by the average gradient of the class score with respect to that channel. Substitute the head from §3:

∂ zc / ∂ Fk(x, y) = ∂ / ∂ Fk(x, y)  [ Σk′ W[c,k′] · (1/49) Σx′,y′ Fk′(x′,y′) + bc ]   =   W[c, k] / 49

The gradient is a constant — it does not depend on x, y or on the image. So Grad-CAM’s channel weight αkc is just W[c,k] / 49, and the map collapses to the original Class Activation Mapping (Zhou et al. 2016):

CAMc(x, y) = ReLU( Σk W[c, k] · Fk(x, y) )

This is exact for any global-average-pool → single-linear head (which is what MobileNetV2 has), needs only a forward pass, and adds ~3.2 ms on one CPU core. The CAM-enabled ONNX produces logits bit-identical to the deployed model.

6.1  Building the heatmap

  1. Select the row. Take W[grade] — the 1280-length weight row for the predicted grade (from the sidecar _cam.npz).
  2. Weighted sum + ReLU. CAM = ReLU(einsum("kij,k->ij", F, W[grade])) → a 7×7 map. ReLU keeps only evidence for the grade.
  3. Normalise to [0,1] by dividing by its own maximum.
  4. Upsample 7×7 → 224×224 with bicubic interpolation.
  5. Colour-map with JET (blue = low, red = high).
  6. Blend over the letterboxed grayscale film with a per-pixel alpha that fades to transparent where the map is cold, so cold regions still show the anatomy.

6.2  Focus region & text

  • Focus region — the intensity-weighted centroid of the 7×7 map plus the spread of its hot cells is mapped to one of: central joint line / one compartment (with a lateral-vs-medial-third hint) / diffuse – bicompartmental. It is deliberately conservative: without the knee’s L/R laterality the system does not claim “medial” vs “lateral” definitively.
  • Templated findings — a fixed phrase set per grade (e.g. KL2 → “definite osteophytes; possible joint-space narrowing”), combined with the focus-region phrase. Clearly labelled AI-generated, not patient-specific.
  • Recommendation — grade-banded (KL0–1 → correlate if symptomatic; KL2 → early-OA management; KL3 → orthopaedic review; KL4 → referral, assess arthroplasty). Overridden by a REFER message when the model abstains.

7How the weights were trained — knowledge distillation

This section is training-time only. None of it runs at inference; it explains where the numbers in W and the backbone came from.

MobileNetV2 tuned on its own plateaued around Macro-F1 0.67. The lift to 0.68–0.69 came from training it to imitate two larger networks rather than only the hard labels.

7.1  Teachers

VGG16 (test Macro-F1 0.74) and ConvNeXt-Tiny (0.72), both frozen from the earlier 15-model benchmark. Their logits were run once over every training image and cached; for each image the two teachers’ softmax outputs (at temperature T = 4) are averaged into a soft target q.

7.2  The loss

L = α · T² · KL( q ‖ softmax(zS / T) )  +  (1 − α) · CE( softmax(zS), ytrue ; class-weights )
  • Soft term — KL divergence between the teacher distribution q and the student’s softened distribution. It transfers the teachers’ “dark knowledge”: which wrong grades are plausible, how close KL1 and KL2 look. The T² factor keeps this term’s gradient on the same scale as the hard term as T grows.
  • Hard term — ordinary weighted cross-entropy against the true grade, with train-only class weights so the rare KL4 (176 training knees) is not ignored.
  • α = 0.8 — 80% of the signal is the teachers, 20% the hard label. (A sweep of α and T picked this.)

7.3  The rest of the recipe

  • Weight EMA — an exponential moving average of the weights (θEMA ← 0.999 θEMA + 0.001 θ per step) is what gets evaluated and exported; it is smoother than the raw end-of-epoch weights.
  • Two-stage transfer — 3 epochs training only the new 5-way head with the backbone frozen, then full fine-tuning; cosine learning-rate schedule with a 1-epoch warm-up; up to 70 epochs with early stopping on validation Macro-F1.
  • Strong-but-medical augmentation as listed in §1.
  • Seed 123 — the deployed checkpoint is the seed selected on validation from a 3-seed run (mean test Macro-F1 0.686 ± 0.007).

What did not help, tested and dropped: mixup, label smoothing, stacking the Phase-7 tuning dimensions, a CORN ordinal head, and int8 quantization.

9Reading the diagram

  • Solid arrows, left–right = the inference data path (this document, §1–6).
  • Teal boxes and arrows = the explainability branch (§6). It taps the feature map F and the classifier row W[grade], and also takes the preprocessed film for the blend.
  • Dashed box, top = the knowledge-distillation objective (§7). Its only connection to the rest is the dashed “student weights” arrow into the backbone — it produced the weights and is otherwise absent at inference.
  • Output card, bottom = what the dashboard assembles from the two paths: grade + confidence, probability bars, OA screen, 3-class band, heatmap, interpretation, recommendation, abstain banner, disclaimer.
